# 吹田市救援物資配送支援システム — V2 계산 개선

기존 `suita_delivery_support(2).zip`을 기반으로 만든 개선판입니다. **기존 P1, UI, 피난소 데이터, 지도 및 롤링 실적 처리 구조는 유지**하고 P0/P2 계산 모듈을 보완했습니다.

## 변경 내용

| 영역 | 변경 | 파일 |
|---|---|---|
| P0 | 대규모 차량·회차 MILP가 장시간 멈추는 경우, 검증된 실행가능 초기 배정을 먼저 만든 뒤 물자량을 **정수 MILP로 재최적화** | `p0_kit_optimizer.py`, `p0_v2_refinement.py` |
| P0 | 고정 방문·차량·회차에 대한 재고·수요·적재량·최소량·보수적 시간 상한을 재검증하고 개선된 F1/η **상계**만 채택 | 동일 |
| P2 | GA·2-opt 후보에 더해, **동일 거점·동일 회차 차량끼리** 방문지 이동과 교환을 탐색 | `p2_kit_optimizer.py`, `p2_v2_routing.py` |
| P2 | 방문 피난소가 7개 이하인 개별 차량 경로에서는 Held–Karp 동적계획법으로 방문 순서를 정확히 계산 (차량 배정 전체의 최적성은 아님) | `p2_v2_routing.py` |
| 표시 | 새 P0·P2 결과 캐시 버전 83에 맞춰 클라이언트 버전 확인 수정, P0 재최적화 설명 정정 | `templates/plan.html`, `templates/routes.html`, `templates/p0.html`, `static/p0_dashboard_v69.js` |
| 검증 | 7개 자동 회귀 테스트 추가 | `tests/test_v2.py` |

**중요:** 대규모 P0는 차량 배정을 전역 최적화한 결과가 아니라, 실행가능 배정에서 배송량을 최적화한 결과입니다. 화면의 `η`는 검증된 **상계**이며, PDF의 이론적 최적값 `η*`가 확인된 것은 아닙니다.

## 실행 방법

1. ZIP을 압축 해제하고 `suita_delivery_support` 폴더에서 실행합니다.
2. Python 가상환경에 `pip install -r requirements.txt`로 Flask·SciPy 등을 설치합니다.
3. 개발용은 `python app.py`, 서버 배포는 기존의 `gunicorn.conf.py` 및 Render 설정을 그대로 사용합니다.
4. 기존 GitHub 저장소에 새 버전의 파일을 반영할 때 **데이터와 기존 파일을 백업**합니다.
5. 프로그램 내부 캐시 버전이 82 → 83으로 변경되므로 **P1 → P0 → P2를 순서대로 다시 계산**합니다. 이전 브라우저에 저장된 P0/P2 계산 결과는 재사용하지 않습니다.

계산 자동 테스트: `python -m unittest discover -s tests -v`

## 실데이터 검증 조건과 결과

- 123개 피난소 중 비축량 조건을 충족한 100개 사용. 그중 추가 배송 가능한 피난소 97개.
- 가상의 1차 시나리오: 1,777인일분(7,996.5kg), 목표 80%, ρ=0.001, 최소 3인일분(13.5kg), 최대 5회차.

## 이후 보완해야 할 사항

1. **F2–F3 다목적 탐색:** PDF의 엄밀한 파레토 최적화가 아니라 제한된 후보집합에서 F2 우선으로 선택합니다. `Δ` 조정에 따른 공평성–조기공급 트레이드오프 분석은 별도 필요합니다.
2. **η 최적성 증명:** 큰 사례에서는 전체 차량 배정을 포함한 MILP의 최적성 증명이 없습니다. 상계와 하계를 반드시 구별해야 합니다.
3. **실도로 및 피해도로:** Google 실도로시간과 우회경로의 실제 호출은 이 시험에서 검증하지 않았습니다. `緊急交通路優先` 모드는 기존과 마찬가지로 미구현입니다.
4. **근접 피난소 80개 대표점:** 이번 정량 검증은 100개 시설 개별 좌표를 대상으로 했습니다. 대표점에서 각 시설로의 최종 물자 전달 절차·하역시간은 별도 검증이 필요합니다.
5. **롤링 실적:** 정상 소규모 실적 확정은 테스트했지만, 실제 수요 갱신·도로피해 갱신을 포함하는 장기간 다회차 시뮬레이션은 별도 시험이 필요합니다.
6. **웹 구동 테스트:** Python·JS·Jinja 템플릿의 구문검사는 통과했으나, 이 검증 환경에 Flask가 설치되어 있지 않아 HTTP 엔드포인트의 실제 실행은 수행하지 못했습니다. Render 배포 후 재확인해야 합니다.

## 실행 검증

- 100개 시설·18대 차량·최대 5회차 시나리오에서 P1 → P0 → P2 정상 완료.
- 배송량 보존, 차량 적재량, 허브별 재고, 시간 제한, F1 상계 충족을 다시 검증.
- 작은 예제 7개 `unittest` 통과. 비대칭 도로시간 행렬·대표점·롤링 실적·미구현 도로 모드 예외 처리 포함.
- 전 Python 소스 `compileall`, JS `node --check`, Jinja 템플릿 파싱 통과.
