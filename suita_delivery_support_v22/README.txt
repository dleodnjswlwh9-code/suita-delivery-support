救援物資配送支援システム v23.4
===========================================
今回の変更: 論文 rev21 の P1 制約を追加、F1* の説明、地図下の長い文章を削除。
ホーム・配分画面の基本レイアウトは v23.3 を維持。

【実行方法】
1. pip install -r requirements.txt
2. python app.py （Render の場合は gunicorn app:app）
3. 「配分計画」で次の2ファイルを読み込みます（順番は自由）。
   ① sample_data/shelters.xlsx：避難所台帳
   ② sample_data/aspiration_targets.xlsx：食料・飲料水の希求水準
4. 「希求水準・調整係数」のρを設定します。
5. 「輸送拠点物資量」で1次・2次・3次の物資量を kg 単位で設定します。
6. その下の「P1の配送能力条件」を設定します。
   - 最小配送量δ（kg）：初期表示0.5kgは暫定の入力例です。研究条件に応じて変更してください。
   - 1期間内の配送回数：24時間の各期間において各車両が出動できる回数（初期表示1回は仮定）。
   - 車両台数：2t・4t・10tを入力。初期0台なので、少なくとも1台の入力が必要です。
7. 「配分計画を実行する」を押します。
   F1*（食料・飲料水を合わせたP1達成関数の最小値）に「?」説明を表示します。

【P1 の反映箇所】
論文「delivery_model_rev21_確定.pdf」4.2節(25)〜(31)、2節(12),(14),(17),(22)に対応。
- 希求水準 a と正規化係数 w=1/(1-a)、ρ>0、θのエピグラフ制約
- 在庫総量と車両の残り総積載能力による上限：配送回数×全車両の積載量
- 各避難所の残余需要・配送回数×最大車両容量による上限
- 追加配送が可能な施設と、残余需要がδより少ない施設の区別
- 未訪問施設への必須配送下限δ（P1の緩和下限）
- 必須訪問施設数に対する最低在庫量・訪問可能枠の事前チェック
- 特定の既訪問・満足施設についてθの制約から除外し、増大項には定数として残す

【論文からの拡張・まだ決定していない事項】
重要: 論文の基本モデルは「単一物資・単一輸送拠点」です。v23.4は
食料と飲料水を同じ車両に積む場合の総重量を二重計上しないため、
2物資を1つの共同線形計画で解く「本研究用の拡張」です。
共同 F1* は食料・飲料水の希求水準未達度を合わせて評価するため、
従来 v23.3 の物資別 F1* とは数値の意味が異なります。

現行データ「備蓄量＋計画上の累計配分量」は、論文の
実際の配送済み量 S^b とは異なります。24時間ごとの3つの計画期は
論文の車両配送回とは別であり、各期の予定配分が予定通り行われたと仮定して
次期計算に渡しています。実配送実績と未訪問情報を観測して更新する
ローリングホライズンは P2 実装後の課題です。

また、北部／南部の2輸送拠点ごとの車両・在庫は本版ではまだ独立管理していません。
本版の物資量・車両数は両拠点の合計として扱います。
実際の配送回への量割当、車両別の仕分け、δ以上の配送を各訪問で強制する
条件、車両の出発・帰還・ルート・時間条件は P0 / P2 で扱うものです。
したがって、本版は P1 の制約を反映した「理想配分の試算」であり、
配送実績・配送確定量ではありません。

- デプロイ先のGoogle Maps API表示は環境変数の設定が必要
