救援物資配送支援システム v23 — 希求水準のExcel読込と上位問題P1の試作

【起動】
1. pip install -r requirements.txt
2. python app.py
3. ブラウザで http://127.0.0.1:5000/allocation
Render: 従来どおり gunicorn app:app （Root Directory はZIP内の suita_delivery_support_v23）

【v23の利用方法】
1. 「配分計画」から sample_data/aspiration_shelters.xlsx またはユーザーの「希求水準データ.xlsx」を1回アップロードする。
   シート「避難所データ」には 名称／食料の希求水準（%）／飲料水の希求水準（%）
   シート「地域別検索・並替」には 地域／名称／緯度／経度／収容可能人数／備蓄量
   を含める。名称を照合し、123件の希求水準と位置・備蓄情報を統合する。
2. 配分方法「希求水準に基づく配分（P1・試算）」を選択する。
   既定のρ=0.01は仮設定。結果を比較し研究上の採用値を決めること。
   希求水準はExcelで各施設別に0%以上100%未満の数値（70など）を指定する。
3. 1次、2次、3次の食品・飲料水の輸送拠点物資量（kg）を入力する。
4. 「配分計画を実行する」を押す。表・グラフ・地図は従来の形で表示する。
   P1を選択すると、避難所別の希求水準と、F1*・従来方式を同じF1で評価した値が追加表示される。
5. 配分方法を「従来方式」に切り替えると、従来の充足率均等化アルゴリズムを利用できる。

【実装したP1の数理】
各物資・各計画期につき、希求水準 a_k、必要量 d_k、配分前確保量 b_k と予算 B を用いる。
変数 x_k（新たな配分量）, θ として、s_k=min(b_k,d_k)+x_k、w_k=1/(1-a_k)、ρ>0。
目的 min F1 = θ + ρ * Σ w_k(a_k-s_k/d_k)
制約 θ >= w_k(a_k-s_k/d_k)（残余需要がある避難所）
      0 <= x_k <= max(0,d_k-b_k), Σx_k <= B
Python scipy.optimize.linprog(method="highs") を使用。
「備蓄量＋計画上の累計配分量」をP1の確保量とみなす現行Webアプリ向けの適用上の仮定がある。

【重要：v23の対象外】
- 本版はP1の主要目的関数と配分枠のみを実装。論文の未訪問施設への最低配分下限δ、P0実装可能性ギャップη、P2の車両割当・経路・F2/F3・Δは未実装。
- 1次～3次は24時間単位の研究上の計画期であり、論文の「車両配送回」と同じではない。
- 1回目から3回目の参考配分は前期分が計画どおり確保されたと仮定して繰り越す。実配送の完了確認、消費・損耗の控除、在庫実績の自動更新はない。
- レトルトご飯と飲料水はこの段階では別々に解く。同じ車両へ同時積載する総重量条件はP0/P2で扱う。
- 北部・南部の2輸送拠点の在庫・車両の別管理は、v23のP1試作にはまだ含めていない。
- 「配送計画」のボタンは現段階では入力条件保存のみ（最適経路探索は行わない）。
- 123施設のうち、元の分析条件に従い、レトルトご飯と飲料水の備蓄がともに正の100施設を計算する。データ未整備の23施設は除外。
- 地域別予想避難者数は data/regional_population.json 内蔵。72時間内の追加人口割当は研究上の仮定であり公式予測ではない。
- ρ=0.01は最終的な研究結論ではない。論文のρ>0という条件を守り、感度分析が必要。
