【配分計画の操作】
 1. 「避難所データ」で .xlsx ファイルを読み込む。
    同梱の例：sample_data/shelters.xlsx
    既存の台帳形式（地域、名称、緯度、経度、収容可能人数、レトルトご飯、飲料水500ml）に対応。
    配分計画で読み込んだデータは配送計画でも再使用される。
 2. 希求水準 70% / 80% / 90% を選ぶ（初期値80%）。
    重み w=1/(1-a) は 3.33 / 5.00 / 10.00 と自動表示。
 3. 輸送拠点物資量（kg）を「総物資量」1欄で入力する。
 4. 配送計画で事前に保存した2t車両・最小配送単位δ・配送回数を自動参照する。配分画面の詳細設定はρのみ。
 5. 「配分計画を実行する」で食料・飲料水の予定配分量を同時に計算。

【計算の定義】
 1避難所の総合充足率 = min(食料充足率, 飲料水充足率)
 g_k = (a - 総合充足率)/(1-a)
 F1 = θ + ρ × Σ g_k
 総物資量の範囲内で食料・飲料水を同時に割り当てる。
 物資ごとの必要量および避難所の既存備蓄量は別々に保持する。
 ρ=0.001、δ=0.5kg は初期設定であり、必要に応じ詳細設定から変更する。
 車両は2tのみ（1台につき積載能力2,000kg）。
 初動の想定避難者数の計算方法および食料1.5kg／人、飲料水3kg／人はv24から継承。

【重要：総物資量の意味】
 総物資量は「配分計算で利用可能と仮定する合計重量」である。
 内訳を入力しないため、実際の輸送拠点に食料・飲料水がそれぞれ計算量だけあるかは確認できない。
 最適化結果に食料・飲料水の必要量が表示されるので、実在庫との照合は別途必要。
 P0・P2が未実装のため、P1で計算した予定量は配送可能性を保証しない。

【研究上の位置づけ】
 教授論文のP1の希求水準法を、2物資に対してひとつの最悪未達度を評価するよう拡張した。
 論文原型（単一物資・既配送量）と完全同一のモデルではない。
 現在の既存備蓄量は論文でいう既配送累積量S^bと意味が異なる。
 希求水準は配分上限ではなく、必要量の100%まで計算上の配分が可能。
 データ未整備（レトルトご飯または飲料水の0記録）は現在も旧設定どおり除外する。
 0が真の欠品を意味するのか、単に未記録なのかはデータ整備時に確認する。

v32 P0 基本形（実計算。P2は未実装）
・v31の元の明るい画面・左メニュー・配置を保持し、配分・配送画面に入力を追加せずP0を実装。
・配送計画で「2tトラック台数」「最小配送単位δ」「配送回数上限」を設定して保存。
・配分計画で同じ車両条件を用いてP1を実行。
・物資輸送経路ページの「P0を計算する」でP0 MILPを実行。
・出力: P1理想評価値、P0実行可能評価値、実装可能性ギャップη、P0の車両/回次別仮割当、避難所別参考配分。
・目標関数はP1と完全に同じ二品目の共同評価 F1=θ+ρΣmax(g_food,g_water)。
・制約: 個別需要、計画上の共通在庫総量、車両1台1回2000kg、訪問した場合は総量δ以上、
  同一配送回の同一避難所への訪問車両は最大1台、未訪問かつ有効残余需要δ以上の避難所は残り回次内に訪問、
  稼働車両は必ず避難所に配送、配送回は第1回から順に使用。
・初期の既存備蓄量は既配送・訪問履歴ではない。全避難所を未訪問として判定。
・P0は北部・南部の個別在庫・個別車両配置をまだ制約にしていない。「共通プールP0基本形」のみ。
・実道路、通行止め、拘束時間、出発/帰着時刻、最短ルート、P2のF2/F3は未計算。
・緊急交通路・一般道路の経路選択用重みはすべて1.0。道路被害率は参照値であり計算に反映しない。
・P0最適化の探索打切り時: 実行可能解がある場合「暫定」と表示（ηの最小性は証明できない）。
・現在の計算上限: 対象避難所 ≤ 200、車両 ≤20、回数 ≤12、対象×車両×回数 ≤2500。
・P0の結果は同じタブのsessionStorageに保存。P1の再計算/条件変更によって古い結果を無効化。
・サーバーでFlaskとSciPyが必要。pip install -r requirements.txt。
・構造上、最終的なP2の配送量/訪問順/経路はまだ確定しない。P0出力を配送確定結果と誤認しないこと。
