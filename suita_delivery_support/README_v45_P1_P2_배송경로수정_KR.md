# v45 — P1 / P2 물자수송경로 개선 (P0 보류)

## 기존 v44에서 변경

1. P1의 피난소별 배송 상한을 논문 4.2절 식 (26)에 맞춰 `min(잔여수요, 남은 회차 × 차량 한 대 적재량)`으로 제한했습니다. *한 피난소는 동일 회차에 차량 한 대만 방문*하는 조건에 대응합니다.
2. 필수 방문의 δ 검사를 재고량과 방문가능 횟수로 분리했습니다. 부족한 경우 필요량/부족량을 에러에 표시합니다. δ는 *최소 배송단위(人日分/피난소/방문)*로 유지하며 별도의 최소 배분단위를 만들지 않았습니다.
3. P1 정수 환산 단계가 0<신규 배송량<δ인 방문을 만들지 않도록 개선했습니다.
4. P2 탐욕적 차량 배정이 실패하는 경우, **작은·중간 규모에서 전체 피난소당 1회 배송으로 적재할 수 있으면** `scipy.optimize.milp`로 차량/거점/회차를 다시 배정합니다. 예: δ=10, 피난소 4곳/차량 3대/1회/총량 900인일분 조건 재현 성공. 이는 배정의 실행 가능성 확인이며 P2 전역 최적성/P0를 증명하지 않습니다.
5. 0명 수요를 인위적으로 1명으로 변경하지 않습니다. P1/P2는 잔여수요 0을 배송 대상에서 제외하고 표에는 충족률 '—'로 표시합니다.
6. P1이 저장한 첫 단계의 이상 평가값 F1*를 P2에 넘겨 *입력 데이터 일치 여부*를 확인합니다. 서로 다르면 조용히 다른 결과를 만들지 않고 재계산을 요구합니다. P2는 운용상 필요한 이유로 P1의 배분 벡터 자체를 고정하지 않습니다.
7. **지도 가독성:** 배송 방향(빨강, 출발 거점→전 피난소), 복귀 방향(파랑 점선, 마지막 피난소→거점), 경로 화살표의 크기/간격을 강화했습니다. 같은 도로에서 복귀선의 흰 테두리가 배송선을 가리지 않도록 조정했습니다. 한 차량을 클릭하면 출발 및 복귀를 각각 **색상 구별된 2개 경로 카드**로 표시하고 전체 피난소 순서 및 Google 도로 구간별 거리·시간을 끝까지 표시합니다. `1台を詳しく見る` 버튼 추가, '배송만/복귀만'을 분리해서 볼 수 있습니다.
8. 기존 P0 API와 `p0_optimizer.py`는 변경하지 않았습니다.

## 사용법

- ZIP을 풀면 `suita_delivery_support/` 폴더에 앱 코드가 있습니다. Render **Root Directory는 빈칸**으로 설정하고 Start Command는 `gunicorn --chdir suita_delivery_support app:app --bind 0.0.0.0:$PORT`입니다.
- 기존 P1 모델이 바뀌었기 때문에 저장된 v44 세션 계획은 새 형식으로 인정되지 않습니다. **배분계획 화면으로 이동해 P1 배분을 다시 계산한 다음 배송 경로를 계산하세요.** (계획 데이터는 브라우저 sessionStorage에 저장됩니다.)
- 배송 지도에서 특정 차량 카드를 선택하거나 `1台を詳しく見る` 버튼을 누르면 개별 차량 노선과 빨강/파랑 각각의 이동 구간을 쉽게 식별할 수 있습니다. `① 配送のみ（赤）`, `② 帰着のみ（青）`로 겹친 도로를 별도 조회합니다. `全経路を表示`로 지도 범위를 복원합니다.
- Google Cloud Maps JavaScript API 및 Routes API를 설정하지 않은 경우 지도의 선은 **도로 경로가 아닌 직선 개략도**입니다.

## 완료하지 않은 것 (추가 연구/개발 범위)

- P0/η*의 정식 구현은 요청에 따라 보류. F1Route-F1Star 값은 **평가 차이**일 뿐, P0의 최적 실현 가능성 갭이 아닙니다.
- P2는 실행 가능성 우선 휴리스틱+GA로, F2/F3의 전역 파레토 최적해 보장이나 100개 피난소 전체 MILP를 제공하지 않습니다. MILP 재배정은 소규모/중간규모의 **1피난소 1회 방문으로 가능한 경우**에 한정됩니다. 분할 배송이 꼭 필요한 복잡한 경우 첫 탐욕 해법이 실패하면 여전히 계산이 중단될 수 있습니다.
- 북/남부의 *실제* 개별 재고·차량대수 입력, 피난소별 Excel 희구수준, 24/48/72시간 동적 롤링 업데이트, 긴급교통로 피해 시나리오, Google 도로시간을 직접 사용하는 Python GA는 아직 추가 구현이 필요합니다. 현재 Google은 도로 형상과 방문순 개선·교통시간 **사후 평가**에 사용됩니다.
- 실제 Google 유료 API 동작, 실제 Google 계정 설정, Render 배포/실사용 성능은 이 환경에서 확인하지 못했습니다.
