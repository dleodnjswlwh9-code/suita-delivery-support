# rev27　救援物資の配分・配送モデルのMATLAB実装

原稿 `delivery_model_rev27.tex` に対応する。論文用の説明例（6避難所・在庫40箱）を、緊急度一律と避難所別の緊急度で解き、図を出力する。ファイル名・関数名・エラー識別子・出力フォルダー名は「rev27」にそろえてある（例：`rev27_run`、`figures_rev27`）。

rev26 の一式（`rev26_matlab_step9`）からの変更は次の2点。論文用の例（9節）の数値は変わらない。

1. **許容幅ごとの最大総追加配送量（原稿4.5項の (P0′)）。** P2 と同じ達成関数の上限（最良実装値＋$\Delta$）の下で配れる最大量 $\overline B_\Delta$ を `rev27_solve_p0total` が求め、P2 はその全量を配る。rev26 までは $\Delta=0$ の最大量を下限にしていた。
2. **目標配分率に達しても配送を続ける（原稿4.7項の手続き2(d)）。** 達成は状態の `targetStatus` に記録するだけで、在庫・受入余地・車両・配送回が許す限り次の配送を計画する。入力に `stopAtTargets = true` を入れると、rev26 までと同じく達成時に終了する。

そのほかの特徴は rev26 と同じ。

* **$\rho=10^{-4}$。** 増大項は弱パレート解を除くためのものとして小さな値を既定にし、小さすぎる値を自動で点検する。
* **例題は1つ。** 緊急度の有無・目標配分率・$\rho$・$\gamma$ を引数で指定する。手順1～7の例題と検算は `tests/` にある。
* **非劣解の選択画面。** 推奨案の基準を `rev27_selection_rule.m` の1か所に書き、画面で利用者が選ぶ。

## MATLABで実行する

このフォルダーを現在のフォルダーにする。Optimization Toolboxを使う。動作確認環境はMATLAB R2026b Update 1（Windows 11）。

```matlab
out = demo_rev27;          % 例題を解き、figures_rev27 に図・CSV・要約・結果を保存（約1～2分）
verify_rev27(out)          % 別のソルバーで独立に求めた値と照合（既定の設定のとき）
```

図の体裁だけを変えるときは、保存済みの結果から描き直せる（約10秒）。

```matlab
R = load(fullfile('figures_rev27','results_figures.mat'));
rev27_figures('figures_rev27',struct('Results',R));
```

## 目標配分率・ρ・緊急度を変える

例題は `rev27_example` で作る。どれも省略でき、省略時は既定値になる。

```matlab
[d,t,xy] = rev27_example;                                   % 緊急度一律、目標配分率0.5、ρ=1e-4
[d,t,xy] = rev27_example(Urgency=true);                     % 避難所別の緊急度 γ=(0.9,1.7,1.0,0.7,0.5,1.2)
[d,t,xy] = rev27_example(TargetRate=0.6);                   % 目標配分率（全避難所に同じ値）
[d,t,xy] = rev27_example(TargetRate=[0.6 0.6 0.5 0.5 0.5 0.5]);   % 避難所別の目標配分率
[d,t,xy] = rev27_example(Rho=1e-3, Urgency=true, Gamma=[1 2 1 1 1 1]);
```

図を作るときは、同じ項目を `rev27_figures`（または `demo_rev27` の第2引数）に渡す。一律と避難所別の両方に同じ値が入る。

```matlab
out = demo_rev27('figs_a06',struct('TargetRate',0.6));      % 別フォルダーに出力
```

| 項目 | 既定値 | 内容 |
|---|---|---|
| `TargetRate` | 0.5 | 目標配分率。スカラーまたは6要素ベクトル（0以上1未満） |
| `Rho` | 1e-4 | 増大項の係数 $\rho$ |
| `Gamma` | [0.9 1.7 1.0 0.7 0.5 1.2] | 避難所別の緊急度（相対値） |
| `KeepTotal` | true | P2の総量下限（許容幅ごとの最大総追加配送量を配る）。`false` にするとrev25までの定式化（総量下限なし。$\Delta$ による総量の減少を許す） |
| `Deltas` | [0 0.02 0.07] | 図5で比べる $\Delta$（0は常に含む。4水準まで） |
| `Formats`、`Resolution`、`Show`、`Results` | `["pdf","png"]`、600、false、なし | 出力形式、解像度、画面表示、保存済みの結果 |

自分で作った入力（構造体）でも、`d.a` に目標配分率を入れて `rev27_run(d,t,[],struct('enumerateFront',true))` で解ける。

* **在庫不足の確認:** 目標配分率を下げて目標量の合計 $\sum_k a_k d_k$ が在庫40箱以下になると、目標量は在庫で賄え、在庫不足の例ではなくなる。このとき `rev27_example` が警告を出す（目標配分率が一律なら、在庫不足の例にするには $a>4/9$ が必要）。ただし実装可能性ギャップが0になるとは限らない。$F_1$ は目標を超えた供給も評価するためで、たとえば一律 $a=0.4$（目標量36箱）では $\eta^*=0.0741$ となる。ギャップの有無は計算結果で確かめる。
* **ρの自動点検（原稿4.6項の目安）:** 1箱の増減が $F_1$ の増大項を動かす最小幅 $\rho\,w_k b/d_k$（追加配送できる避難所での最小値）が $10^{-6}$ より小さいと、`rev27_prepare` が警告を出す。もう一つの目安（$\rho\sum_k w_k$ が1箱分の変化 $\min_k w_k b/d_k$ より十分小さいこと）は、状態の `rhoSumEffect` と `boxStep` に値を記録する（この例では $1.2\times10^{-3}$ と $0.067$）。この幅が許容誤差に埋もれると、弱パレート解を除く働きが失われる。この例では $\rho=10^{-4}$ で約 $7\times10^{-6}$。需要の大きい実データでは、この警告で値を確かめる。
* **期待値は既定の設定だけ:** `verify_rev27` は既定の設定についてだけ期待値をもつ。設定を変えた結果を渡すと、照合を省略したと表示する。

## 総量下限と Δ の意味

P2は $F_1$ を最小化せず、$F_1(s)\le F_1(s^{P0})+\Delta$ を上限条件として $F_2$・$F_3$ を最小化する。$F_2$ には荷の量に比例する荷役時間が含まれるので、上限に余裕があると配る量を減らす計画が非劣解になる。$\rho$ が小さいと、配り残しが $F_1$ をほとんど悪化させないため、$\Delta$ の余裕がほぼ配り残しに使われる。

そこで、同じ上限の下で配れる最大量を先に求め、P2 にはその全量を配ることを課す（`keepTotal`、既定 true）。

$$\overline{B}_\Delta=\max\Bigl\{\textstyle\sum_k (s_k-\hat S_k)\ :\ s\ \text{は運用実行可能で}\ F_1(s)\le F_1(s^{P0})+\Delta\Bigr\},\qquad \sum_k (s_k-\hat S_k)\ \ge\ \overline{B}_\Delta$$

* **求め方:** `rev27_solve_p0total` が (P0) と同じ運用制約（`rev27_p0_model`）で解く。結果は `r.p2.minAddedBoxes`（箱）、最大性を確認できたかは `r.p2.totalCertified` に入る。
* **解き直しの省略:** P0 の計画が既に在庫・受入余地・車両容量の上限まで配っていれば、どの $\Delta$ でも最大量は同じなので解き直さない（論文用の例はこの場合で、どの $\Delta$ でも40箱）。
* **$\Delta$ を広げると最大量が増える場合:** 最良実装値を保つと配り切れない在庫が、少し譲ると配れることがある。原稿4.5項の2避難所例では、$\Delta=0$ で3箱、$\Delta\ge0.000025$ で4箱になる（`tests/verify_rev27_manuscript` で照合）。
* **$\Delta=0$ の最大量:** `r.p0.maxAddedBoxes` にも入る。P0の最適解は一つに定まらないため、代表解の総量ではなく「最良実装値を保つ配分の最大総量」を使う。

最大量が変わらない範囲では、$\rho$ が小さいとき $\Delta$ は「最も不足している避難所の正規化未達度を、最良実装値からどこまで悪化させてよいか」という意味になる。論文用の例では、効き方は次のように段階的になる。

| $\Delta$ | 許される変化 |
|---|---|
| 0 | 最良の $F_1$ を与える配分は35通り（避難所1・2が12・8箱、残り20箱を避難所3～6に各4箱以上）。非劣解の最終配分はすべて [12 8 5 5 5 5] で、非劣解の間の違いは配送の順序と経路 |
| 0.02（0より大きく約0.06665未満） | 最も低い供給率0.4を保ったまま、余りの4箱の行き先を変えられる（例：[12 10 5 4 5 4]） |
| 0.07（約0.06665以上。境界は数値許容誤差を除いて 4999/75000 = 0.0666533…） | 避難所1を11箱（供給率0.367）に下げ、その1箱を他の避難所に回せる |

## 非劣解から計画を選ぶ

```matlab
[d,t] = rev27_example(Urgency=true);
r = rev27_run(d,t,[],struct('enumerateFront',true,'Delta',0.02));
choice = rev27_select_plan(r);        % 画面で選ぶ。choice.point.plan に箱数・経路
```

* **選択画面（`rev27_selection_screen`）の構成:**
  * 左：非劣解の図。推奨案を橙の円で、選択中の案を四角で示す。
  * 右：候補表。$F_2$、$F_3$、基準項、遅れ項、総箱数、今回の箱数、最終配分を並べる。
  * 下：推奨の理由、採用理由の入力欄、「推奨案で決定」「選択中の案で決定」「保留」のボタン。
  * 図の点か表の行をクリックして選ぶ。
* **コマンドウィンドウでの選択:** 画面を開けない環境では、表とID入力に切り替わる。Enterで推奨案、0で保留になる。`rev27_select_plan(r,"text")` で指定してもよい。`"none"` を渡すと、画面を出さずに推奨案を採用する。
* **推奨の基準を変える:** `rev27_selection_rule.m` の冒頭の設定欄を書き換える。規則は次のとおり。
  * `"extraMinutes"`（既定）：最短の完了時刻から15分以内の案のうち、$F_3$ が最小の案。
  * `"F3Limit"`：$F_3$ が上限以下の案のうち、$F_2$ が最短の案。
  * `"minF2"`、`"minF3"`。
  * `"weighted"`：0～1に正規化した重み付き和が最小の案。
  * `"custom"`：`customScore` に自由に書いた評価値が最小の案。例として「緊急度が最も高い避難所に今回の回で配る案を優先」を載せてある。
* **ローリング計算での選択:** `rev27_run_rolling` で `selection="manual"` にすると、各回でこの画面が開く（`screen` で `"window"` か `"text"` を指定できる）。`selection="recommend"` にすると、推奨案を画面なしで採用する。決定記録（`out.decisions`）には推奨ID・理由・採用ID・利用者の理由が残る。

## 検算

* **`verify_rev27`:** 次の値を照合する。期待値は、経路変数をすべて明示した混合整数計画を、別のソルバー（Python・HiGHS）で解いて求めた。
  * $F_1^*$、$\eta^*$、各 $\Delta$ の最大総追加配送量40箱
  * $\Delta=0$ の非劣解と最終配分
  * $F_2$ 最小の計画の回別箱数と $F_3$ の内訳
  * 他方の重みでの評価値
  * 各 $\Delta$ の非劣解、配送総量、最低供給率
* **`tests/run_all_tests`:** 手順1～7と第4.7項の回帰検査（rev25原稿の手計算例、$\rho=0.1$）。総量下限なし（rev25までの定式化）の動作と、総量下限ありの動作の両方を確かめる。2避難所の例では、P2と同じ上限の下での最大総量を全列挙で独立に求めて照合する。最後に `verify_rev27_manuscript` が、rev27原稿の本文中の手計算例（4.5項、4.7項の2例、6.4項、7節、8節。いずれも $\rho=10^{-4}$）を照合する。
* **`tests/check_selection_screen`:** 画面を開き、自動で第3案を選んで記録を確かめる。数秒間ウィンドウが開く。
* **結果の記録:** 実行結果は `verified_output.txt` にある。
