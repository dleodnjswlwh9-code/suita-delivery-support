# rev25 手順7　配送実績を反映するローリングホライズン計算

配送回の開始時に、現在の在庫・需要・既配送量を使って残りの配送回を計画し、今回分だけを実行する。帰着後に受領量と補給を記録し、次の回で配分・車両・経路を解き直す。研究用の小規模厳密解法として、手順6のP2を使う。

## 第4.7項第5・6号　候補の提示と実行案の選択

**第5号**では各観測時点 $h$ で、残り全回を対象としてP2を解く。P0の箱数から再計算した $F_1(s^{P0})$ に $\Delta$ と数値許容幅を足した値がP2の配分上限である。P0の厳密解では $F_1^{(h)*}+\eta^{(h)*}$ に対応し、暫定解ではその配分から求めた上界を使う。`p2.p0Optimal` で区別する。当回の使用は $u_h=1$ に固定する。

**第6号**では、得られた非劣目的ベクトルごとに代表計画を1件提示する。表の $F_2,F_3$ は残り計画全体の値で、今回の所要時間・避難所別箱数・経路・受領後も未訪問の地点・補給前の拠点在庫を併記する。採用IDと選択基準を記録して、その計画の今回分だけを実行する。次の回では新しい実績でP1・P0・P2を解き直し、複数候補なら再び選ぶ。最終回の $F_3$ は空和で0となり、最小 $F_2$ を与える目的ベクトルは1点となる。同じ目的値を持つ複数の経路・割当があるときは総走行時間が最小の代表計画を表示する。

### 同じ第1回の候補からA案とB案を比較する

```matlab
[d,t] = rev27_example('paper92_two');
p = rev27_run_rolling(d,t,struct('selection',"review"));   % 候補を表示して配送前に返る
disp(p.decisions{end}.candidates)
A = rev27_apply_choice(p,1);                              % 表のID 1の今回分を実行
B = rev27_apply_choice(p,2,"初回に両避難所へ届ける");      % 任意で採用理由を記録
```

| 初回の候補 | 計画 $F_2$（分） | 計画 $F_3$ | 今回の配送（避難所1・2、箱） | 今回の所要（分） | 第2回開始時の在庫（箱） | 第2回開始時の未訪問数 | 累積稼働（分） |
|---|---:|---:|---|---:|---:|---:|---:|
| A（ID 1） | 68 | 9 | 18・0 | 34 | 18 | 1 | 68 |
| B（ID 2） | 83 | 8 | 18・2 | 50 | 16 | 0 | 83 |

これは同じ初期在庫36箱、補給・需要更新なしで比較した代表計画である。両案とも最終的に各避難所が18箱ずつ受領する。選択後に同じ時点を再求解せず、保留時に実際に表示した箱数・経路を使う。第2回以降にも複数案が現れた場合は、その時点で返った結果に対して `rev27_apply_choice` を再度実行する。選択保留中は在庫・既配送量・配送回と帰着後イベントを保持する。以前の時点の候補IDは新しい時点には引き継がない。

### 第1回の帰着後に車両容量が20箱から16箱に減る場合

同じ初回候補A・Bについて、車両1台の第2回の容量を20箱と16箱の2通りで比較した。各避難所の需要は20箱、目標はその90%に当たる18箱である。補給は0箱とし、需要と移動・荷役時間は全ケースで同じ値を使った。第1回は全ケースとも容量20箱で計画し、選んだ案の第1回分を実行した。容量減少を観測したケースでは、第1回の帰着後に `Q = 16*b` を反映し、第2回のP1・P0・P2を解き直した。

| 初回案 | 第2回容量（箱） | 第1回配送（避難所1・2） | 第2回配送（避難所1・2） | 最終受領（避難所1・2） | 最終供給率（避難所1・2） | 目標までの不足（避難所1・2） | 最終在庫（箱） | 稼働時間（第1回＋第2回） |
|---|---:|---|---|---|---|---|---:|---|
| A | 20 | 18・0箱 | 0・18箱 | 18・18箱 | 90%・90% | 0・0箱 | 0 | 34＋34＝68分 |
| A | 16 | 18・0箱 | 0・16箱 | 18・16箱 | 90%・80% | 0・2箱 | 2 | 34＋33＝67分 |
| B | 20 | 18・2箱 | 0・16箱 | 18・18箱 | 90%・90% | 0・0箱 | 0 | 50＋33＝83分 |
| B | 16 | 18・2箱 | 0・16箱 | 18・18箱 | 90%・90% | 0・0箱 | 0 | 50＋33＝83分 |

Aでは第2回の出発前に18箱が残り、容量が16箱に減ると2箱が拠点に残る。避難所2の最終受領は16箱で、目標18箱まで2箱不足する。所要時間が1分短くなるのは、荷卸しが2箱分減るためである。Bでは初回に避難所2にも2箱を届けており、第2回の残庫16箱を全量配送できる。初回に15分長い計画を選んだ効果が、この条件では最終供給率に現れる。

最終回の $F_3$ は4ケースとも空和で0である。期末の目標達否は避難所別の供給率と不足箱数で確認する。容量減少時のAは、避難所2の重み付き未達が $10(0.9-0.8)=1$、避難所1の未達が0なので、達成関数は $F_1=1+0.1(1+0)=1.1$ となる。他の3ケースは $F_1=0$ である。4ケースすべてについて、第2回の実行可能な整数配分を全列挙し、最良の配分評価とその下での最短所要時間を照合した。

```matlab
x = demo_rev27_step7_capacity_change;
disp(x.comparison)                % 4ケースの回別・期末の数値
disp(x.reduced.A.shelters)         % 容量減少時にAを選んだ場合の避難所別実績
disp(x.reduced.B.history)          % 容量減少時にBを選んだ場合の各回の予測と実績
```

### 選択規則

| 指定例（`rev27_run_rolling` の第3引数） | 動作 |
|---|---|
| `struct('selection',"manual")` | 候補表を表示し、複数ならコマンドウィンドウでIDを入力。Enterまたは0で保留。キーボード入力が使えないバッチ実行でも選択待ちで返る |
| `struct('selection',"review")` | 複数なら `selection_pending` として戻る。保存した候補を見て `rev27_apply_choice(p,ID)` で選ぶ |
| `struct('F2Limit',75)` | 原稿の自動規則。残り計画の $F_2\le75$ 分の下で $F_3$ を最小化。同じ $F_3$ なら $F_2$ を最小化 |
| `struct('extraMinutes',15)` | 当回で求めた最短の $F_2$ に15分を加えた時間を上限として同様に選ぶ |
| `struct('F3Limit',8)` | $F_3\le8$ の下で $F_2$ を最小化。同じ $F_2$ なら $F_3$ を最小化。引数を省略した既定値は `Inf` |

自動上限にはスカラー、または実際の回 $1,\ldots,R_{\max}$ に対応するベクトルを指定できる。上限を満たす計画がなければ配送前に `policy_infeasible` を返す。時間上限はその値をMILPに課して評価する。2避難所例では上限75分でA、83分でB、67.9分では実行不能となる。手動入力では `2 初回に両避難所へ届ける` のように選択理由も残せる。保留中に開始時の在庫・需要・道路情報や政策を改訂した場合は、その条件で候補表を更新してから選ぶ。外部で候補を表示してIDを返す場合は `struct('selection',"manual",'choose',@(h,c) ...)` を指定できる。関数には現在回とその候補表が渡り、IDまたは保留を示す0を返す。

### 全非劣点の確認範囲

手順7は毎回、両端点を辞書式に求め、異なる場合はその間の非劣点を適応的に探索する。箱数に由来する $F_3$ の格子、または各便の走行・積込・箱単位荷卸しに由来する $F_2$ の格子を数値許容誤差の範囲で検証する。格子を確認できない入力では、各回の最長車両の時間の和から、実現し得る $F_2$ の間隔も検査する。目的値が数値精度に近くこの間隔を証明できない場合は、$F_3$ の数値分解能を明示して走査する。この場合は `fullFront=false` と表示する。`out.decisions{j}` に、その時点の候補表、確認方法、選択規則、実効上限、選択ID・保留状態を保存する。原稿の2避難所例と、$\Delta=0.55$ の1避難所例では、それぞれ全2点・全6点を確認した。

## 自分の入力で計算する

```matlab
[d,timing] = rev27_example('six');
policy = struct('F3Limit',2.5,'Delta',0);
change.d = d.d; change.d(1) = 40*d.b;        % 全避難所の更新後の需要（物資量）
change.replenishment = 5*d.b;                % 箱数を物資量に換算
events.afterRound{1} = change;               % 第1回が終わってから反映
x = rev27_run_rolling(d,timing,policy,events);
```

第3・第4引数は省略できる。配分評価の政策許容幅は既定 $\Delta=0$。`Delta`、`numericTolerance`、`objectiveTolerance`、`maxTime` の意味は `README_step6.md` のとおり。

### 回のどの時点で反映するか

| 入力 | 反映の時点・単位 |
|---|---|
| `events.afterRound{h}.actual.boxes` | 回 $h$ の受領実績。避難所×車両の非負整数箱数。省略時は採択計画の当回分 |
| `actual.routes` | 車両ごとの実走経路を格納したセル。拠点0で発着し、待機は `[]`。省略時は計画経路 |
| `actual.truckMinutes` | 当回の車両別の実測所要分。省略時は実走経路・出動・受領量から算定。回の稼働時間は最長の車両の値 |
| `replenishment` | 帰着後に拠点に加わる物資量。省略時は0 |
| `d, a, gamma` | 帰着後に観測した需要、目標配分率、緊急度。変更する項目ごとに同じ避難所順のベクトルを指定 |
| `Q, delta, timing` | 次回に使う車両容量、最小訪問量、時間入力。車両別の移動時間を使い台数を変える場合は、新しい台数に合う `timing` も指定 |
| `events.onPause{h}` | 資源不足時に同じ回で反映する更新。補給・状態更新に加えて `waitMinutes` を指定できる。複数回待つ場合は更新構造体をセルで時系列に並べる |

配送中に一部を持ち戻った場合は、各避難所が受け取った数量だけを在庫から差し引く。計画経路を走っても受領が0箱なら、その地点の累積受領量は増えない。便自体の取り消しを表すには、当該車両の箱数を0、実走経路を空にする。全車両が出発を取り消したときは同じ回で待機し、帰着後に予定した補給や需要更新は実際に出動した回の帰着後に反映する。別の経路を実走した場合は受領先を含む実走経路を指定する。各回の実績も、在庫・車両容量・残余需要、同一回の同一避難所は1台までの条件と照合する。

たとえば1避難所例で初回の計画が10箱でも、実際に受領した数量が6箱、車両の実所要時間が37分なら、次のように記録する。

```matlab
[d,timing] = rev27_example('paper92_one');
ev = struct();
ev.afterRound{1}.actual = struct('boxes',6,'truckMinutes',37);
x = rev27_run_rolling(d,timing,struct(),ev);
```

### 在庫・時間・終了判定

- 避難所 $k$ の累積受領量には、当回の実受領箱数に1箱の物資量 $b$ を掛けて加算する。次回の拠点在庫は「出発前在庫 − 当回の実受領総量 ＋ 帰着後の補給量」。箱未満の在庫端数も引き継ぐ。
- 次回は更新後の状態から活性集合・必須訪問先・未達度を求め、P1・P0・P2を再計算する。各回の配分上限は、その回のP0配分による $F_1$ に $\Delta$ と数値許容幅を加えた値である。
- `out.operatingMinutes` は実行した回の車両別所要時間の最大値を足したもの。`out.waitingMinutes` は累積待機分。`history.ForecastF2Minutes` と `ForecastF3` は毎回の残り期間全体の予測である。`ActualWeightedShortfall` は各回開始時の需要・重みで評価した当回受領後の不足で、最終回は評価対象外を示す `NaN` になる。
- `completed` は最終回の実行完了で、更新後の状態を $h=R_{\max}+1$ として報告する。`stopped` は目標達成・資源消尽などによる途中終了。`paused` は資源更新または出動の再開を待つ状態。`policy_infeasible` は当回の政策上限を満たす計画がない状態。`selection_pending` は意思決定者の選択を待つ状態である。上限不成立時・選択保留時は `blockedSolution.p2.front` に候補が残る。
- 待機中に更新を受けた場合は、同じ $h$ で再判定する。目標達成などの終了条件を優先する。初回の需要が最小訪問量以上という仮定は初回観測で確認する。その後、同じ回で待機中に需要が最小訪問量を下回った地点は訪問対象外となり、需要が再び増えれば必須訪問先に戻り得る。途中で一度結果を返したときは `nextData`、`nextTiming`、未消費の `remainingEvents` を次回の入力に使える。再開時の稼働時間・実配送箱数はその再開区間分で、避難所別の累積受領量は全期間分である。
- 終了時の `shelters` 表には、未訪問、必須未完了、訪問対象外、目標達否、名目・有効残余需要を避難所別に示す。訪問実績の判定には正の受領量を使う。`EverExcluded` は、いずれかの観測時点で未訪問かつ対象外と判定された履歴を示す。
