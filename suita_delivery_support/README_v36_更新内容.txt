v36 수정 — 요청사항 반영 (2026-10-22)

1. 配送計画
- 재해조건 아래의 「道路被害率（参考値）」, 「道路啓開段階 STEP0~」 표시 제거.
- 재해강도·발재 후 경과시간 입력 및 원래 지도는 유지.
- 최소배송단위는 1인일분 이상 정수, 10인일분도 정상 계산 가능.

2. 物資輸送経路
- 상단 P1/P0/P2 단계 흐름 표시 제거. 내부 P1/P0/P2 함수 역할은 유지.
- 계산 전 도로 모드 선택 메뉴:
    すべての道路を利用  : 기존 기본 P2 경로 탐색을 사용 (현행 이동시간은 Manhattan 거리/20km/h 근사).
    緊急交通路を優先 : 선택 가능하지만 미구현. 이 상태에서 계산 버튼 비활성화 및 계산 API도 요청 거부.
- 실제 API 키 설정 시 Google 지도 기반에 수송거점, 차량별 방문지 및 경로 표시.
- 전체 차량 보기: Google 지도 위에 방문 순서를 연결한 개략선.
- 한 차량 보기: Google DirectionsService로 도로상의 주행경로를 조회(호출마다 과금/쿼터 가능).
  Google Maps JavaScript API와 Directions 서비스 사용 가능 상태 및 GOOGLE_MAPS_API_KEY 설정 필요.
  DirectionsService는 Google 측에서 2026년 2월부터 deprecated이며 현재 동작하지만 추후 이관 필요.
- 중요: Google 지도 경로는 결과 화면의 참고 표시 전용. P2 최적화의 F2에는 아직 Google 주행시간이 입력되지 않음.
  따라서 구글 도로 이동경로를 표시하더라도 P2 계산 결과가 실제 도로 최단시간이라는 뜻은 아님.
- 키가 없는 실행환경은 개략도 SVG로 대체.

3. 최소배송량 10 수정
- P1 정수화에서 1~9인일분의 새 배송이 생기지 않도록 변경.
- P2 탐색에서 트럭 잔여용량 < δ인 새 방문 후보를 제거.
- 이미 배송받는 피난소의 남은 물자가 δ 미만이면 기존 회차에 합치거나 다른 회차로 δ만큼 이동하여 검증된 정수 배송안 구성.
- 100개 대상 피난소, 차량 10대, 최대 8회, δ=10,
  공급량 1,000/5,000/10,000/20,000/30,000인일분 5개 사례 계산·검증 통과.
- 공급량 자체가 필수 방문 최소량보다 적거나 차량·회차 용량이 부족한 경우에는 정당한 계산 불능이 가능.

4. 配分計画
- 기존 表 / 避難所別 그래프는 유지.
- 「充足率分布」탭 추가: 실제 배분 대상 100개 피난소의 충족률을 0~10%, ... 90~100%로 나누고
  각 구간의 배분 전/후 피난소 수를 표시. 동일 70/80/90% 희구수준의 분포가 아닌 실제 충족률 분포.

5. 서체/정리
- 원래 파란색 상단·흰색 사이드바·메뉴 구조 유지.
- 본문의 주요 수치·버튼·표·경로 정보 가독성 개선.
- 배송 화면에서 중복된 회색 부연 설명 제거하고 실제 계산 상태/오류 문구만 유지.

미구현·유의
- P0 최적화 및 η* 미계산(임시 η=0). 조건 미달 시 참고안 표시.
- 긴급교통로 경로 가중치/도로파괴율은 계산에 사용하지 않음.
- 24~72시간 재고·피난자 갱신은 4단계 예정.
- 두 거점의 실제 분리재고 미확정, 경로 탐색은 근사해법. 전역 최적성 보장 안 됨.
- Flask 서버 통합 동작은 현재 실행환경에 Flask 설치가 없어 검사하지 못함.
