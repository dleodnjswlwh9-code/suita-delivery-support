# P1／P2 complete-kit implementation, v34 (2026-10-21)

## Status, model attribution and limits

This release edits the existing v33 Flask application and makes `/routes` a **working P2 prototype**, rather than a fictitious `?preview=1` rendering. The P2 route construction / visit permutation GA / 2-opt / Or-opt is heuristic; results are NOT proven globally optimal. It does not claim to implement the full reference MILP in the professor's paper.

Original reference: `二段階複数回配送モデル(4).pdf` (38 pp), esp. §2, §4.2–4.7, eqs. (44)–(77), §6.2–6.3, §8.

**P0 remains deferred**, and `/api/p0-optimize` returns HTTP 501. Legacy P0 source code is retained in `p0_optimizer.py` for later reference but is NOT linked to the new kit model. The interim eta setting in P2 is **0**, NOT a certified result from P0.

`/routes` displays a **provisional route**, with a prominent message if its actual integer-kit F1 score violates `F1 <= F1*` under eta=0. Such a route meets the *physical* checks but is NOT a feasible solution of the strict professor P2 model. It must not be used as a validated model result until P0 has been implemented or the upper-level assessment is otherwise made feasible.

## One complete kit, units and P1

- One person-day kit: 3 retort rice meals + six 500ml water bottles.
- Shelter initial full kits = `min(floor(retortRice / 3), floor(water500ml / 6))`. The unmated residual meals/bottles remain in the original shelter registry; they **cannot** be counted as full kits and are NOT otherwise allocated in this version.
- Shelter 1-day demand in kits: existing initial shelter-population estimate (existing v33 regional population apportionment method). The 23 excluded shelters are not used in optimization.
- Shared initial shipment stock is entered as person-day kits, replacing kilograms. For existing user sessions the old kg entry does **not** silently migrate.
- One kit weighs **4.5kg**, a *research assumption*: meals `3×0.5 kg` + water `6×0.5 kg`; no packaging mass or vehicle volume. A 2t truck can carry at most **444 complete kits** by mass.
- The P1 endpoint is `/api/p1-kits`; one commodity, continuous LP, selectable aspiration 0.70/0.80/0.90 and `w=1/(1-a)`, positive rho, mandatory visits with minimum kit quantities. Its F1 optimum value is NOT a final dispatched allocation.
- The P2 endpoint is `/api/p2-kits`. It generates integer kit quantities and vehicle tours, independently checks per-shelter demand, stock, loading capacity, same-round unique vehicle service and mandatory visits. The P1 optimum vector is currently used as an **initial integer allocation seed**; this is a disclosed heuristic difference from the paper's true simultaneous P2 optimization of quantities and routes.

## F2 / F3 / route time

- `F2 = sum_r H_r`, `H_r = max_t T_tr` for same-round simultaneous truck departures and a global synchronized round clock across the two hubs.
- A truck's visit route is from its assigned hub, visits one or more shelters, and returns to the same hub; truck reused in later rounds.
- Truck operating time: **city-block approximate driving time at 20 km/h** + `30 minutes × 1 loading per dispatched truck/round` + `15 minutes × visited shelters` + `0.04 minutes × delivered kits`. The last two values adapt Yagi's case study. A 30-minute loading period is a research assumption extrapolated from recent relief logistic preparations, NOT a standard measured 2t loading time.
- `F3 = sum_{r=1}^{Rmax-1} sum_k w max(0, a - (B_k + cumulative_delivered_kr) / d_k)`. It uses the **fixed evaluation window** prescribed by the professor; it does not skip trailing unused rounds.
- Route insertion and mutation GA, 2-opt and Or-opt optimize travel, with within-round transfer/swap repairs reducing F2 makespan. The current implementation does NOT certify a lexicographic global F2/F3 optimum; F3 is calculated and later delivery is biased against, but the optimizer is not an exact multiobjective solver.
- Distances are **Manhattan/rectangular geographic estimates**, not actual road links. The SVG view connects the stops with approximate lines and expressly says so. The later emergency-road scenario is **NOT** implemented.

## Priorities left unresolved (must not be silently guessed)

1. **P0 true eta**. With integer kits and vehicle constraints, eta=0 often makes the strict P2 condition infeasible. The reference route must not be reported as the professor model's final admissible solution while `isValidatedP2=false`.
2. **True combined kit inventories**. The 23 data-missing shelters are excluded. The original registry can have more standalone meals than matched water, or vice versa; separate unmet components are ignored in the complete-kit planning assumption.
3. **Hub-level physical inventory and truck assignment**. Currently global stock and fleet are split using a heuristic; source-confirmed north/south stocks have not been assigned.
4. **Actual street network travel times / true drawn paths**. The system currently displays geographical straight connectors, not navigable road segments. Need directed links and shortest travel-time path per origin/destination for a real route map.
5. **Loading/unloading assumptions**. Need measured or better sourced times and pallet/labor availability; service time is per visit plus per kit. Concurrent loading for all active trucks is assumed.
6. **Rmax**. Defaults to 8 rounds only as a configurable computational starting point; setting its fixed F3 evaluation horizon according to the research time window requires validation. Eight rounds are not eight 24-hour periods.
7. **0–72 hours**. Stage 4 (24-hour stocks, demand consumption, hub replenishment, rolling execution of only the current round, pre-24hr local warehousing) is **NOT implemented** here.
8. **Optimality validation**. GA heuristic needs controlled random seeds, repeated runs, small MILP exact comparisons, stronger mutations and improved quantity optimization. Current passing unit tests validate mathematical constraints on generated cases, not global optimality.
